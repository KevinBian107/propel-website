Concise

Fewer words per fact, not fewer facts. The claim comes first and its evidence follows; restatement, narration and empty hedges go; every evidence item in the draft survives the rewrite.

Shorter Is Not the Goal

A rewrite that drops a file:line, a number or a caveat is not concise, it is lossy. For a finished write-up the skill checks this with a script and, where Codex is enabled, a second model compares the draft against the rewrite. Neither check decides anything: a missing item is restored, and you read the result.

Overview

Concise is a writing discipline for responses and written artifacts: investigation READMEs, design docs, retrospective entries, docs pages and other long write-ups. It is active in all four modes. For chat replies the rules are self-applied, with no script and no Codex. For a finished write-up the skill saves the draft, rewrites it, checks with claim-check.sh that no extracted evidence token went missing, and has Codex compare the draft against the rewrite — inside the consult the artifact already gets at its gate, or as a standalone Writeup review for a substantively rewritten docs page or long write-up outside scratch/.

Every turnroute.sh carries rule 7: "Claim first, then its evidence; cut narration and restatement; never drop evidence (concise skill)." This is how the rules reach ordinary replies

The Rules

#Rule
1Claim before evidence. Lead with the claim; the evidence follows it, never the reverse.
2Every evidence item survives. file:line references, numbers, test results, command output, decisions, attributions ([claude], [codex]) and links stay in the rewrite.
3Cut what carries nothing. Restatement, narration of process ("I then looked at…"), hedges with no information, preamble and recap, adjectives doing no work.
4One idea per sentence. Tables for parallel facts; bullets nested no deeper than two levels.
5Keep uncertainty that informs. "unverified" and "not tested on tmux" are evidence about the claim, not hedges.

Finished Write-Ups — The Procedure

Run the script from the repo root: bash .claude/scripts/claim-check.sh in a project that uses Propel (bash scripts/claim-check.sh in Propel's own source tree).

  1. Save the draft with claim-check.sh --save-draft <artifact>. It copies the artifact under .propel/concise/, naming it after the artifact's repo-relative path with every / replaced by __, plus .draft.md, and prints that path: scratch/2026-11-18-x/README.md becomes .propel/concise/scratch__2026-11-18-x__README.md.draft.md. If a draft for that artifact is already pending, it refuses to overwrite it (exit 1). A draft is stale only when its gate is visibly answered (in the conversation, or recorded in the artifact); it is deleted and replaced. Any other pending draft, including one from an earlier session or from before a /clear, is the baseline: it may be the only copy of the original text, so it is kept and the rewrite is checked against it.
  2. Rewrite the artifact in place, by the five rules. A template with a fixed section order (a registry entry, the investigation README, the Gate 2 summary) keeps that order; claim-first applies within each section.
  3. Check: claim-check.sh <draft path> <artifact> reports every evidence token the rewrite dropped.
  4. Restore every missing token and re-run until exit 0. Rule 2 has no exceptions: a missing item goes back in, never "removed X".
  5. Read for meaning. Compare draft and rewrite claim by claim for what no script can see: a dropped "not" or "only", a lost caveat, a swapped result, a bare integer, a unit it doesn't know.
  6. Codex compares draft and rewrite, if Codex is enabled (see below). Each finding is verified against the two files before anything changes.
  7. Present the rewrite. The draft is kept until you accept the rewrite. For a gate write-up (Gate 1, Gate 2, retrospective), answering the gate question counts as accepting the rewrite; there is no separate “accept the rewrite?” question next to it.
  8. Clean up. Once you accept it (for a gate write-up: right after you answer the gate), the draft is deleted. A draft left behind blocks the next --save-draft of that artifact, which is how an unaccepted rewrite stays visible.

claim-check.sh

A bash-and-awk script (no python3), so "every evidence item survives" is checked, not remembered:

bash .claude/scripts/claim-check.sh FILE                # list FILE's evidence tokens, with counts
bash .claude/scripts/claim-check.sh DRAFT REWRITE       # tokens DRAFT has that REWRITE lost
bash .claude/scripts/claim-check.sh --save-draft FILE   # copy FILE to its draft path; never overwrites

It extracts backtick spans, URLs (balanced parentheses kept), attribution tags ([claude], [codex], [both], and qualified forms like [codex · unverified]), path:line references, ratios (125/125, 0/0/0), commit hashes, numbers that carry a decimal point, an exponent, a % or a unit (91.2%, lr=3e-4, 3 epochs, 12 ms), and results (3 failed, 120 passed). A sign alone does not make a number a token: a leading + or - is kept as part of a number that already qualifies (-0.5, +3%), but -3 by itself is a bare integer. Bare integers are not tokens. Reflowing a paragraph does not change a token.

LineMeaning
missingThe token is gone from the rewrite; printed with its class and first draft line. The only kind that changes the exit status
fewerInformational: the token is kept with a lower count, as cutting a restatement does
unquotedInformational: a backtick span lost its backticks, but its text is still there
ExitMeaning
0No extracted token is missing (--save-draft: saved)
1Some token is missing from the rewrite (--save-draft: a draft is already pending)
2Usage error, or a file is missing or unreadable
3Internal error
Exit 0 is not proof that nothing was lost. A rewrite can keep every token and still invert the meaning (“fast failed; safe passed” with the two swapped), and words like “not” or “only”, a caveat, or a bare integer are not tokens. The script catches dropped evidence; changed meaning is what the Codex comparison and your own reading are for.

The Codex Comparison

The writeup-review question: is any claim, caveat or evidence item lost or changed, and where does a reader meet evidence before the claim it supports? It is the one Codex question that passes paths, the saved draft and the rewrite, because a review of the final text alone cannot see what was dropped. Codex reads both files in the repository and answers under the heading Writeup review:. Because Codex reads those files directly, bypassing redaction, the question is skipped (and Claude says so) if either holds secrets, credentials or unpublished data.

ArtifactHow Codex sees it
Investigation findings (Gate 1), design doc (Gate 2), retrospective entryFolded into that gate's own consult: one call, two questions, and it counts as the writeup review. The gate's material is inlined as before; only the writeup question gets paths. The ledger records --question "<gate question> + writeup review"
A finished docs page, or a long write-up outside scratch/, with no consult of its ownA standalone Writeup review consult, only when the rewrite changed about 30 or more lines of prose (the Gate 3 threshold)
scratch/ working notes, trivial or formatting-only edits, chat repliesNever. The same rewrite is never reviewed twice

Findings come back verified and attributed like every other consult; see Codex Consult. With Codex disabled, the script and the reading still run and the gate is single-model.

Guardrails

GuardrailWhy
Restore every missing token"Concise" means fewer words per fact; a dropped fact is a lost result, not a tighter sentence.
Treat exit 0 as "no token missing", never as "nothing lost"Tokens survive a meaning inversion; the script cannot read.
Keep informative uncertaintyCutting "unverified" turns a hypothesis into a claim.
Give Codex both paths for the writeup question; skip it if either file holds secretsOnly the draft shows what the rewrite dropped, and Codex reads the files unredacted.
Keep the draft until the rewrite is accepted; never overwrite a pending oneThe draft is the evidence of what was there.
Rewrite prose only — never code, quoted output or logsEvidence is copied verbatim, not paraphrased.
No script and no Codex for chat replies or scratch/ notesThe per-turn rule is enough there; a consult per reply would be noise.
